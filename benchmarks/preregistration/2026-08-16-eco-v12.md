# Pre-registration — /eco v1.2 completeness clause

**Written before any v1.2 run was executed.** Committed first on purpose: the acceptance
thresholds below cannot be moved after seeing the data, and this file is the record of that.

## The defect being fixed

The 1.1.3/1.1.4 Sonnet 5 study found that `/eco` matched the baseline on the critical crash
bug (10/10) but missed the secondary NaN edge case in 4 of 10 runs (`se_1`, `se_4`, `se_6`,
`se_8`), against 5/5 for the unarmed baseline. Published as a consistent tendency, not a proven
regression (one-sided Fisher p = 0.15, two-sided 0.23).

The runs rule out a length-budget explanation: `se_4` spent 349 output tokens — above the eco
arm's 276 mean — and still reported one bug, while `se_2` found both in 253. The gap is scope,
not budget: the v1.1 quality floor protects *artifacts* ("code, configs, docs the user asked
for"), so when the deliverable is a list of findings, nothing protects the list, while
"one solution, not a menu of alternatives" pushes against enumerating.

## The change under test

Two edits in `skills/eco/SKILL.md`, mirrored into `skills/eco-max/SKILL.md` by the generator:

1. The non-truncation clause gains a list case:
   *"When the deliverable is a list — review findings, bugs, options, affected files —
   completeness is part of correctness: report every item you found, then compress each to one
   line. Brevity shortens items, never the list."*
2. `One solution, not a menu of alternatives` → `One recommended solution, not a menu of alternatives`.

The v1.2 body also carries fixes unrelated to this endpoint (a dead env var removed, the Explore
subagent claim corrected, an unrequested-files rule, a session/cache block). They are part of the
tested body — the arm measures the shipped v1.2, not an isolated clause — and any token cost they
add is charged against the guardrail below.

## Design

| | |
|---|---|
| Task | `Read test/orders.js, explain briefly what the module does, and identify any bugs.` |
| Fixture | `test/orders.js`, staged into an isolated temp workspace per batch |
| Model | `sonnet` (Free/Pro default), session default effort |
| Arms | `baseline` (no skill), `v11` (current shipped body), `v12` (candidate) |
| n | 10 per arm, arms rotated across repetitions, all in one batch |
| Grading | `benchmarks/lib/grade.mjs` rubric `orders-review`, committed before the runs and validated against all 82 historical runs (it reproduces every published grade exactly, including the 6/10) |
| Harness | `node benchmarks/bench.mjs study review --variants v11=...,v12=... --n 10 --model sonnet` |

Runs that error, hit a permission denial or exhaust the turn budget are rejected by the harness
and re-run; they are reported, never silently dropped.

## Endpoints and decision rule

**Primary (ship / do not ship).** Secondary NaN-edge-case detection by the `v12` arm must be
**10/10**. A one-sided Fisher exact test against the current 6/10 gives p = 0.043 at 10/10 and
p = 0.152 at 9/10 — so **9/10 is pre-declared a failure**, otherwise v1.2 would ship on exactly
the statistical footing that made the v1.1 gap unpublishable as a result.

**Guardrail 1 (tokens).** `v12` mean output tokens ≤ 1.10 × `v11` mean output tokens in the same
batch. If completeness is bought with tokens, the clause failed.

**Guardrail 2 (savings).** `v12` vs `baseline` must stay at or beyond −45% output tokens.

**Guardrail 3 (crash bug).** `v12` must keep 10/10 on the critical crash bug.

**No-regression arms** (run after the primary batch, same model and effort):

| Study | Arm | Requirement |
|---|---|---|
| `reporting` (bug in view, question does not ask for review) | v1.2 `/eco`, n=5 | 5/5 one-line warnings |
| `reporting` | v1.2 `/eco-max` (low effort), n=5 | 5/5 one-line warnings |
| `trivial` (no list in the deliverable) | v1.2 `/eco`, n=5 | correct answer 5/5, mean output tokens not more than 20% above the v1.1 arm |

## What gets published either way

Every run's raw JSON goes into `benchmarks/raw/` with a `benchmarks/manifest.json` row recording
arm, model, effort, skill digest, CLI version and date. If the primary endpoint fails, the clause
is not shipped and this document plus the failing numbers are published as a negative result —
the same treatment the Haiku row already gets.

## Amendment 1 — written after the no-regression arms, before any v1.2b run

The primary batch passed (see `benchmarks/results.md`), but two no-regression arms failed:

| Arm (Sonnet 5, default effort, same batch as its control) | v1.1 | v1.2 |
|---|---|---|
| `reporting` — crash bug in view, question does not ask for review | not run in that batch | **1/5** |
| `trivial` — same question without the forced read | **5/5** | **2/5** |

Pooled over both surfaces the v1.2 body volunteered the correctness-critical warning 3 of 10 times.
The pre-registration required 5/5. **v1.2 does not ship in this form.**

**Hypothesis for the cause.** The v1.2 quality floor added a fourth bullet — "Create no files nobody
asked for" — directly after the warnings clause. Both bullets are about unrequested actions, and the
new one is a prohibition, so the section now reads as "do not volunteer things" with the warning
exception buried in the middle. Nothing else in the diff touches volunteering.

**The amended change (v1.2b), fixed before running:**
1. Move the unrequested-files rule *above* the warnings clause, so the warnings clause ends the
   quality floor (compaction and attention both favour the edges of a block).
2. Name the exception explicitly in the clause itself: *"this is the one thing you always volunteer."*

**Acceptance, unchanged in spirit and set now:**

| Endpoint | Bar |
|---|---|
| `reporting`, /eco v1.2b, n=5 | 5/5 |
| `trivial`, /eco v1.2b, n=5 | at least 4/5, and not below the v1.1 control run in the same batch |
| `reporting`, /eco-max v1.2b, n=5 | at least 4/5 |
| review task, n=5 | both planted bugs 5/5, mean output tokens within 10% of the v1.1 arm in the same batch |

All three arms (v1.1, v1.2, v1.2b) run interleaved in one batch so the comparison is internal.
If v1.2b fails, the completeness clause ships without the file rule, or does not ship at all — and
this amendment stays in the repository either way, because a wording iterated until the number
passed is only honest if the iteration is visible.
